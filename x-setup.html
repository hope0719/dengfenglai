先确认：你要使用哪种发布方式？

这篇教程用于配置 X 官方 API 直发。连接后，在等风来里勾选 X 并确认发布，会直接调用 X 的官方接口。

使用自己的 X 开发者账户，费用也由该账户承担。

接入资格、额度和价格由 X 管理。先到 X 开发者控制台 ↗确认账户状态，并查看 X 官方价格与额度 ↗。本教程不进行充值或订阅操作。

如果只想先用起来，可以不填 Client ID，继续使用跳转到 X、填入内容后由你手动发布的方式。

准备好：已安装的等风来、已登录的 X 账号，以及自己的 X 开发者应用。没有开发者账号或应用时，先在官方控制台按实际要求申请和创建；申请问题请如实填写。下面从已进入应用详情页开始。

第 1 步 · 在等风来里操作

复制“当前插件的回调地址”

  1. 在 Chrome 打开等风来的扩展设置，左侧点发布设置。
  2. 找到 X 发布方式，展开如何配置自己的 X 开发者应用。
  3. 在“当前插件的回调地址”下面，点复制回调地址，留待下一步粘贴。

做到这里：你已经复制了自己当前安装版本的回调地址。请原样使用；换浏览器、换开发版加载目录或扩展 ID 变化后，要重新核对。

第 2 步 · 在 X 控制台操作

打开应用设置，照表填写

在 X 开发者控制台 ↗左侧点 Apps，点开自己的应用。已有认证配置时点 Settings；尚未配置时，在 OAuth 2.0 Keys 区域点 Set up。

页面上的英文怎么选、怎么填
App permissions选择 Read and write（读取和发帖）。无需选择包含 Direct message 的选项。
Request email from users保持关闭，本流程不需要用户邮箱。
Type of App选择 Native App / Public client（公开客户端）。
Callback URI / Redirect URL粘贴第 1 步从你自己的插件复制的回调地址。
Website URL填写等风来的产品页面，例如 Chrome 商店详情页 ↗的完整网址。

完成后点击底部 Save Changes（保存更改）。其他字段按 X 当前页面的实际要求填写。

页面说明中，App permissions 对应 OAuth 1.0a；等风来的 OAuth 2.0 权限还会在第 5 步由 X 单独列出，请在那里核对实际授权范围。

做到这里：X 应用已保存认证配置，接下来可以找到 OAuth 2.0 Client ID。

第 3 步 · 仍在 X 控制台

只复制 Client ID 这一项

返回应用详情的 Keys & Tokens 页面，找到 OAuth 2.0 Keys，复制其中 Client ID 下方的整段文字。

Client ID 是应用编号；Client Secret 是密钥。

等风来这里只接收公开的 Client ID。不要填 Consumer Key、Bearer Token、Access Token 或 Client Secret。如果保存时弹出密钥提示，也只复制 Client ID。

第 4 步 · 回到等风来

粘贴 Client ID，打开授权

  1. 切回插件的发布设置 → X 发布方式。
  2. 在自己的 X 应用 Client ID输入框里，粘贴刚才复制的 Client ID。
  3. 阅读并勾选下方费用说明。
  4. 点击保存并授权 X。

做到这里：Chrome 应打开 X 官方授权页面。打开页面还不代表连接成功。

第 5 步 · 在 X 官方页面确认

看懂英文授权页，再点黑色按钮

左侧会显示 “你的应用名 wants to access permissions on your account”，意思是“这个应用请求访问你的账号”。示例应用叫“等风来 123”，你会看到自己创建的应用名。

  1. 核对应用和账号。应用名下面的 @账号 应是你想连接的 X 账号；不对时先切换账号。
  2. 阅读右侧权限。确认你接受下方说明中的访问范围。
  3. 勾选 I trust this app。意思是“我信任此应用”，截图中已勾选。
  4. 接受权限及页面列出的 X 条款后，点击底部黑色 Authorize app（授权应用）。不接受可点灰色 Cancel（取消）。

右侧这些英文是什么意思？

Stay connected to your account…

保持连接，直到你撤销授权，减少反复登录。

Upload media like photos and videos…

允许代你上传图片和视频。当前等风来发帖链路使用所选图片。

Post and repost for you.

允许代你发帖和转帖。授权后，插件里勾选 X 并确认发布会直接发送。

All the posts you can view…

允许读取你能看到的帖子，包括受保护账号的帖子。

Any account you can view…

允许读取你能查看的账号信息，包括受保护账号。

这是截图中的实际权限范围。该页面没有列出私信或邮箱权限；若你实际看到额外权限，请先核对应用与设置。

做到这里：点击授权后等待跳转。下一步回到插件检查结果。

第 6 步 · 最后核对一次

看到“已授权 @你的账号”，才算连好

回到等风来的发布设置 → X 发布方式，查看顶部状态。当前插件的成功文案如下：

已授权 @你的账号：勾选 X 发布时走官方 API，费用由你的开发者账户承担。

上面是成功提示的文字说明，不是本次已连接成功的截图。此教程尚未补入成功状态实拍。

若仍显示“未授权 API”，或出现错误，说明尚未完成连接。保留错误文字后，按下面的问题排查。

授权成功与发布成功是两件事。

连接完成不会自动发送稿件。以后在编辑器里勾选 X、核对正文和图片、确认发布，才会调用 API；发布是否成功以实际返回结果为准。

以后不想用 API 了怎么办？

在插件里点击断开 X API，恢复手动发布方式。也可到 X 的已连接应用页面 ↗撤销对应应用的授权。

卡住了，先看这里

找不到 Client ID，只有一堆 Token

先确认应用的用户认证已配置，并选择 Native App / Public client。回到 Keys & Tokens，向下找到 OAuth 2.0 Keys。不要复制 OAuth 1.0 或 App-Only Authentication 区域里的内容。

X 提示 Not a valid URL format

确认网址包含 https://，没有空格。Website URL 可直接复制产品商店页的完整地址；包含中文的链接可使用浏览器复制出来的 URL 编码地址。回调地址则从插件的“复制回调地址”按钮原样复制。

授权页面提示回调地址不匹配

重新从当前插件复制回调地址，与 X 应用里的 Callback URI / Redirect URL 逐字核对并保存，再从插件重新发起授权。注意结尾的 /x-oauth，以及是否换过扩展版本或加载目录。

点了授权，插件仍显示未授权或报错

保存完整错误文字，检查 Client ID 是否来自自己的 OAuth 2.0 应用、回调地址是否一致。若页面还在等待跳转，先等它完成。不要通过重新生成密钥来盲目重试。

连接成功了，发布还是失败

先看发布错误提示，再到 X 控制台检查账户接入状态、额度或余额。连接成功只说明授权完成，不保证每次发布请求都能成功。

不想申请开发者账号，还能用吗？

可以。保留手动方式，由插件跳转、插入内容，最后由你在 X 确认发布。无需为了使用手动方式配置 Client ID。

可以先收藏这页，下次更换浏览器或重新授权时再对照。
